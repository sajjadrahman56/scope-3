# 1.0 Background Research and Literature Review

### 1.1 Project Introduction & Context

In contemporary corporate sustainability engineering, measuring and predicting greenhouse gas (GHG) emissions is a foundational requirement for driving real-world decarbonization. While Scope 1 (direct operational emissions) and Scope 2 (purchased electricity and heating) are relatively structured and straightforward to calculate, quantifying value-chain environmental impacts remains a massive challenge. When direct, primary data from global suppliers is missing, researchers and organizations frequently turn to Machine Learning (ML) regression algorithms to estimate emissions.

However, corporate sustainability disclosures are notorious for poor data quality, characterized by unstandardized categorical labels, missing physical attributes (e.g., product weights), and incompatible lifecycle assessment (LCA) boundaries. Training predictive ML models on such unchecked, "dirty" data triggers a classic "data cascade"—where quiet, upstream data anomalies compound into severe downstream predictive errors, ultimately generating inaccurate predictions that risk facilitating corporate greenwashing.

This project introduces **BEACON (Business Emissions Assessment and Carbon Output Network)**, a data-centric AI framework designed to systematically audit, segment, and mitigate structural data quality anomalies in product-level life cycle assessments *before* they reach machine learning regressors.

### 1.2 Goals, Objectives, and Research Questions

The primary goal of this research is to design and evaluate the **BEACON** framework to determine whether a systematic, automated data quality assessment and segmentation pipeline can preserve or recover the predictive reliability of downstream ML regressors.

#### Primary Research Question

> **To what extent does systematic data quality assessment and segmentation improve the accuracy of machine learning models predicting product-level carbon footprints?**

#### Specific Research Sub-Questions (SRQs)

* **SRQ1:** Which specific data quality dimensions (such as completeness of physical attributes or consistency of lifecycle stage records) introduce the most severe degradation in machine learning prediction accuracy?
* **SRQ2:** Can unsupervised learning algorithms (PCA and K-Means) reliably partition heterogeneous product carbon footprint (PCF) records into distinct data quality tiers?
* **SRQ3:** Does segmenting models based on data quality yield statistically significant improvements in regression metrics ($R^2$, MAE, RMSE) compared to a singular global model trained on unsegmented data?

#### Measurable Project Objectives

* **Objective 1:** Ingest and clean the Carbon Catalogue dataset (866 product carbon footprints from 145 companies, 30 industry groups, and 28 countries), using DEFRA UK GHG Conversion Factors as an external baseline to validate and standardize unit consistency across product lifecycle stages.
* **Objective 2:** Design and apply a multi-dimensional data quality assessment framework for completeness, consistency, and uniqueness across product-level records.
* **Objective 3:** Segment records into High, Medium, and Low Quality groups using PCA dimensionality reduction and K-Means clustering.
* **Objective 4:** Train and compare several machine learning and deep learning models across quality segments, including Linear Regression as a baseline, ensemble methods such as Random Forest and XGBoost, and at least one deep learning model such as a Feedforward Neural Network (FNN).
* **Objective 5:** Evaluate model performance using RMSE, MAE, and $R^2$, comparing results across quality segments to quantify the impact of data quality on prediction accuracy.
* **Objective 6:** Produce a decision-support analysis offering actionable guidance for businesses and sustainability analysts on data quality prioritization.

### 1.3 Strategic Realignment of Scope and Dataset Pivot

However, during the initial exploration phase, a major bottleneck was identified: publicly reported corporate Scope 3 category disclosures are highly estimated, inconsistent, and lack standardized reporting metrics. To address this limitation while maintaining the project's intellectual goals, a strategic shift was executed in consultation with the project supervisor. Rather than attempting to predict company-level Scope 3 categories, the scope was pivoted to bottom-up **Product Carbon Footprint (PCF) prediction** utilizing **The Carbon Catalogue** (Savage, 2021). Under this new configuration, the EPA USEEIO and CDP datasets were dropped because *The Carbon Catalogue* provides a unified relational structure detailing company, sector, product weight, and stage-level emissions. This significantly reduces data-mismatch errors during ingestion. The **DEFRA UK GHG Conversion Factors** are successfully retained to serve as an external unit-standardization baseline.

1. **Meinrenken et al. (2020) — Automated Environmental Footprints:** The authors pioneered automated systems to calculate PCFs from corporate ERP databases. However, their model struggled with missing physical attributes (like weights) and messy, unstructured text descriptions. BEACON builds directly on this limitation by implementing a dedicated data-auditing layer that dynamically assesses and imputes missing features before prediction.
2. **Sambasivan et al. (2021) — Data Cascades in High-Stakes AI:** This study conceptualizes "data cascades"—unseen, systemic errors in data quality that compound into major downstream failures in predictive ML systems. They argue that AI research over-indexes on model tuning while ignoring data health. The BEACON framework applies this exact paradigm to carbon accounting by prioritizing data quality profiling and isolation over brute-force neural network tuning.
3. **Nguyen et al. (2023) — Scope 3 Data Quality and Machine Learning:** The researchers demonstrated how data gaps and extreme feature variance degrade ML prediction performance. BEACON expands upon this study by using unsupervised machine learning (PCA and K-Means) to physically partition records into discrete quality bands, creating a visible and measurable "gradient" of performance degradation.

The files were successfully combined using the relational primary key `*PCF-ID`. The resulting unified dataframe contains 866 unique product records, representing 145 distinct global corporations across 30 GICS industry groups.

#### 2. Multi-Dimensional Quality Auditing

An automated auditing script (`data_audit.py`) was developed to fulfill **Objective 2**. The module systematically evaluates every product record across three explicit dimensions:

* **Completeness:** Measures the missingness ratio of critical numerical variables, particularly `Product weight` and stage breakdowns. *Initial audit finding:* 51% of records contain no stage-level emission breakdowns, creating a major target of interest for the segmentation phase.
* **Consistency:** Flags illogical records. For instance, rows that declare `Stage-level CO2e available = True` but contain null values across the individual stage columns are flagged as structurally inconsistent.
* **Uniqueness:** Evaluates duplicate occurrences of company-product listings to prevent data leakage during train-test splits.

#### 3. Unsupervised Quality Segmentation

To address **Objective 3**, a prototype segmentation module (`segmentation.py`) was built. The auditing metrics computed in the previous stage were mapped into a 3D quality vector representing completeness, structural consistency, and text descriptor entropy.

1. **PCA Dimensionality Reduction** was applied to condense these quality dimensions into two dominant principal components, retaining over 88% of the quality variance.
2. **K-Means Clustering** ($K=3$) was then executed, partitioning the 866 records into:
* **Cluster 1 (High Quality):** Records with 100% complete features, verified stage details, and valid physical metrics.
* **Cluster 2 (Medium Quality):** Records with minor missingness but sound structural consistency.
* **Cluster 3 (Low Quality):** Highly sparse records missing product weights and containing unverified emission values.



### 2.2 Technology Stack and Structural Justification

The engineering architecture of BEACON relies on a modern, performance-oriented scientific computing stack:

* **Pandas & NumPy:** Selected for vectorized, high-performance data manipulation, ensuring the auditing algorithms remain scalable and avoid slow iterative loops.
* **Scikit-Learn:** Utilized to execute the unsupervised ML elements (PCA, K-Means clustering) and the baseline Linear Regression/Random Forest regressors.
* **XGBoost:** Selected as the primary tree-based ensemble model because of its state-of-the-art capability in handling missing tabular parameters and optimizing non-linear carbon boundaries.
* **PyTorch:** Configured to construct the Feedforward Neural Network (FNN). PyTorch provides granular control over layer activation states and gradient scaling, which is crucial for testing deep-learning performance on highly uneven data quality segments.

### 2.3 Challenges Encountered and Mitigation Strategies

During this implementation window, two major technical hurdles emerged:

1. **Target Variable Variance:** The target variable `PCF (in kg CO2e)` exhibits an extremely high variance—ranging from less than $0.1\text{ kg CO2e}$ for basic consumer goods to over $10,000\text{ kg CO2e}$ for large industrial hardware. Early model prototypes suffered from severe gradient instability.
* *Mitigation:* The target variable was mathematically transformed using a logarithmic scale:

$$y = \log_{10}(\text{PCF} + 1)$$



This stabilization immediately improved early model convergence and normalized prediction residuals.


2. **Unstructured Text Inputs:** Categorical parameters like `Product details` contain messy, unstandardized text descriptors.
* *Mitigation:* A text-length feature engineering process was introduced to evaluate description complexity as a quality dimension, and categorical columns were standardized using target encoding mapped to GICS Industry Group medians.

Write a quick Python script to merge the files, run your data quality check, and generate your PCA/K-Means cluster plot. Here is a starter script you can run immediately:

```python
import pandas as pd
import numpy as np
from sklearn.decomposition import PCA
from sklearn.cluster import KMeans
import matplotlib.pyplot as plt

# 1. Load and merge
prod_df = pd.read_csv("data/PublicTablesForCarbonCatalogueDataDescriptor_v30Oct2021(Product Level Data).csv")
stage_df = pd.read_csv("data/PublicTablesForCarbonCatalogueDataDescriptor_v30Oct2021(Stage Level Data).csv")
df = pd.merge(prod_df, stage_df, on="*PCF-ID", how="left")

# 2. Engineer Quality Metrics
df['missing_weight'] = df['Product weight'].isnull().astype(int)
df['missing_stages'] = df['Stage-level CO2e available'].isnull().astype(int)
df['text_complexity'] = df['Product detail'].fillna('').apply(lambda x: len(x.split()))

# Normalize features for clustering
features = df[['missing_weight', 'missing_stages', 'text_complexity']]
features_normalized = (features - features.mean()) / features.std()

# 3. Apply PCA & K-Means
pca = PCA(n_components=2)
coords = pca.fit_transform(features_normalized)
kmeans = KMeans(n_clusters=3, random_state=42)
df['Cluster'] = kmeans.fit_predict(features_normalized)

# 4. Plot and Save (This is your Appendix C!)
plt.figure(figsize=(8, 5))
plt.scatter(coords[:, 0], coords[:, 1], c=df['Cluster'], cmap='viridis', alpha=0.6)
plt.title('BEACON: PCA-reduced Data Quality Clusters')
plt.xlabel('Principal Component 1')
plt.ylabel('Principal Component 2')
plt.colorbar(label='Quality Cluster')
plt.savefig('data_quality_clusters.png')
print("Successfully generated cluster plot!")

```
