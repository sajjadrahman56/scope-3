# 4. But don't try to improve every score

This is very important.

You shouldn't say:

> "My objective is to make every BEACON score 100%."

That would be methodologically questionable.

For example, your **Representativeness = 84.98%**.

R15 is only **69.97%**.

That doesn't necessarily mean:

> "We should modify the data until it gets 100%."

The dataset is a historical empirical dataset. If certain industries or countries are underrepresented, that may be a **real characteristic of the dataset**.

Your own methodology explicitly defines representativeness as assessing diversity and coverage of the dataset. 

So you should distinguish:

### Correctable data-quality problems

Examples:

* missing values
* incorrect data type
* invalid domain
* inconsistent units
* impossible numerical values
* duplicate IDs
* inconsistent terminology

### Structural limitations

Examples:

* too few products from one industry
* geographic imbalance
* uneven distribution of companies
* historical reporting bias

The second category shouldn't necessarily be "cleaned away."

# 9. One VERY important thing

Do **NOT** use:

```text
Carbon Intensity
```

as an input feature.

Because:

[
Carbon\ Intensity =
\frac{PCF}{Product\ Weight}
]

and your target is:

[
PCF
]

So if you give the model Carbon Intensity, you're essentially giving the model a mathematical transformation of the answer.

That's **target leakage**.

Your current 34-column dataframe doesn't show Carbon Intensity, which is good.

# 10. Company being float64 is not necessarily a problem

You showed:

```text
Company    float64
```

That probably means you have encoded Company numerically.

For example:

```text
PRAN → 1
BMW → 2
Apple → 3
```

That's okay technically, **but we need to be careful**.

If you use:

```text
PRAN = 1
BMW = 2
Apple = 3
```

a model may interpret:

> Apple is "greater" than BMW.

That ordering doesn't have meaningful semantics.

So for some models, we should consider:

* one-hot encoding,
* target/frequency encoding,
* embeddings,
* or another appropriate representation.

And for ANN/XGBoost, the representation needs to be chosen carefully.
